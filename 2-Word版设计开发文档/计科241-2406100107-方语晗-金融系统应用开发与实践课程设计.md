## 一、 项目设计思路与业务场景

### 1.1 选题背景与金融业务场景
随着移动金融科技的飞速发展与移动支付的普及，个人金融资产管理与日常消费记账已成为金融信息系统中的重要应用场景。针对当代大学生及年轻群体在日常生活中面临的多渠道金融账户分散（工商银行储蓄卡、招商银行理财卡、微信支付零钱通、支付宝余额宝等）、月度财务预算失控超支、流水对账繁琐等痛点，本项目自主选题并设计开发了一款轻量级、原生 Android 个人金融资产记账与管理系统——**【金钥匙 (FinanceLedger)】**。

该系统紧密围绕《金融系统应用开发与实践》课程考核要求，打造操作流畅、功能完备、界面现代且架构清晰的移动金融应用，全面涵盖金融账户资产看板、多维度收支记账、跨页面交易凭证传递、历史交易流水对账以及金融综合服务矩阵。

### 1.2 核心业务流程与系统架构
1. **主界面（MainActivity - 金融记账与资产总览）**：
   - 顶部设置账户总资产净值、今日支出与今日收入三项动态统计看板；
   - 中部提供金融快速记账表单，支持切换交易类型（日常支出 / 理财收入）、输入金额、下拉选择结算资产渠道、输入备注并勾选金融增值特性（硬性预算限额、大额重要提醒、定时到期通知），同时提供一键重置清空表单功能；
   - 底部提供一键保存与跳转明细功能。
2. **明细界面（LedgerDetailActivity - 财务明细与服务矩阵）**：
   - 负责接收 MainActivity 跨页面传递的最新交易数据包（Intent 显式传值），以高亮凭证卡片的形式展示该笔金融交易明细；
   - 提供 6 宫格金融服务矩阵（GridView）以及可独立滑动的收支明细清单（ListView），用户可点击任意流水项调出完整的【金融电子对账单详情】对话框。

### 3.1 Activity 页面跳转与 Intent 传值机制
在 Android 体系中，Intent 是组件之间通信的核心载体。在 MainActivity 中，数据打包与跳转代码如下：
```java
Intent intent = new Intent(MainActivity.this, LedgerDetailActivity.class);
intent.putExtra("EXTRA_TYPE", lastType);
intent.putExtra("EXTRA_AMOUNT", lastAmount);
intent.putExtra("EXTRA_ACCOUNT", lastAccount);
intent.putExtra("EXTRA_REMARK", lastRemark);
intent.putExtra("EXTRA_IS_BUDGET", lastIsBudget);
intent.putExtra("EXTRA_IS_URGENT", lastIsUrgent);
intent.putExtra("EXTRA_IS_REMIND", lastIsRemind);
```

### 3.2 列表视图与适配器模式（ListView & BaseAdapter / ViewHolder）
在展示金融交易记录时，为保证滚动流畅并节约系统资源，自定义 `RecordAdapter` 继承了 `BaseAdapter`，并采用了经典的 ViewHolder 模式避免重复执行 `findViewById` 操作：
```java
public View getView(int position, View convertView, ViewGroup parent) {
    ViewHolder holder;
    if (convertView == null) {
        convertView = inflater.inflate(R.layout.item_record, parent, false);
        holder = new ViewHolder();
        holder.tvTitle = convertView.findViewById(R.id.tv_record_title);
        holder.tvAmount = convertView.findViewById(R.id.tv_record_amount);
        convertView.setTag(holder);
    } else {
        holder = (ViewHolder) convertView.getTag();
    }
    // 根据支出/收入设置不同色彩与货币符号...
    return convertView;
}
```

### 3.3 网格布局与业务服务矩阵（GridView）
利用 `GridView` 搭配 `FinanceGridAdapter`，设定 `numColumns=3` 和 `stretchMode=columnWidth`，将“资产分析、预算预警、理财估算、流水对账、汇率换算、系统说明”等常用金融服务模块整齐排列，赋予应用真实的金融业务生态感。

### 3.4 输入有效性校验与异常防护机制
针对用户输入金额的行为，结合 `TextUtils.isEmpty()` 与 `try-catch` 块防范 `NumberFormatException`，确保当输入空值或非数字时能通过 `etAmount.setError()` 进行友好拦截提示，避免程序因异常崩溃。

## 四、 开发过程中遇到的问题及解决方案

### 4.1 XML 清单文件首行声明缩进引发的编译错误
- **【问题现象】**：在执行 Gradle assembleDebug 时报错：`ManifestMerger2$MergeFailureException: Error parsing AndroidManifest.xml`。
- **【原因分析】**：排查发现 `AndroidManifest.xml` 的第一行代码前存在若干空格字符。XML 标准规范明确规定，XML 声明（`<?xml ...?>`）前严禁包含任何空格或回车字符。
- **【解决方案】**：清除第一行声明前的所有缩进字符，使 `<?xml` 紧贴文件第 1 字符，重新编译后成功通过。

### 4.2 输入框金额空值与非法数值的防护
- **【问题现象】**：若用户直接点击记账保存而未输入金额，`Double.parseDouble()` 将抛出 `NumberFormatException` 导致应用闪退。
- **【解决方案】**：在转换前加入 `TextUtils.isEmpty(amountStr)` 判断，配合 `try-catch` 异常捕获；若数值小于等于0则调用 `etAmount.setError("金额必须大于0元！")` 阻止保存并弹出 Toast 提示。

### 4.3 ListView 与 GridView 同屏展示时的滑动与高度适配
- **【问题现象】**：在 `LedgerDetailActivity` 中同时放置 GridView 与 ListView 时，若直接放入外层 ScrollView 会导致列表高度坍塌且滑动冲突。
- **【解决方案】**：取消外层 ScrollView，改用线性分权布局：GridView 设定固定高度（约 130dp，展示两行宫格），而 ListView 设置 `layout_height="0dp"` 且 `layout_weight="1"`，让其自动占据剩余高度并保持自身独立滑动，布局整洁美观且无任何滑动冲突。

### 4.4 移动端输入法软键盘遮挡输入框与自动收起体验
- **【问题现象】**：在输入备注或金额时，弹出的软键盘可能遮挡下方的按钮，且点击保存后软键盘依然驻留屏幕。
- **【解决方案】**：在 `AndroidManifest.xml` 中为 Activity 配置 `windowSoftInputMode="adjustResize"`，使布局自适应上移；同时编写 `hideKeyboard()` 方法，在用户点击确认记账后调用 `InputMethodManager` 自动收起软键盘，提升交互体验。
